Import definitions & make maps

Import a TunerPro XDF or ASAM A2L and open any map in the editor, or promote a findmaps region / manual selection into a named map. This closes the import→edit loop — the editor can now edit maps that were never pre-defined.

Map editor

Decode a defined calibration map out of the opened image into a blue→red heat grid with real axis breakpoints, units and scaling — then edit it. Writing back takes a full-image backup first, applies inverse scaling, and offers a checksum fix.

Double-click a cell to type a value. Click-drag or shift-click selects a rectangle. Edits are clamped to the definition's physical min/max where set; the raw value is rounded and clamped to the data type on write.

File target only in this build. Writing to a real ECU is not validated, so this panel always writes into an image file through the file driver. There is no battery to measure, so the voltage gate is skipped. The whole target file is archived to the opentune-vault folder beside it before the write.

Project

Save a tuning session as a small .otproj file: the base image it was built against (plus a fingerprint to catch a changed image), the selected definition and checksum, and the map edits you made — what you changed, not a copy of the dump. Opening a project re-decodes each map from the referenced image and restores your values on top.

Edits in this project

Each row is one map you changed. An edit stores the edited values and the originally-decoded baseline — never the whole image. Open re-decodes the map from the base image and lays your values back on top; if the base image's fingerprint no longer matches, that is flagged above.

About & updates

OpenTune checks GitHub releases for a signed update. Nothing is downloaded until you ask, nothing is installed without a valid signature, and an update can never start while a flash or map write-back is running.
