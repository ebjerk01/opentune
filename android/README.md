# OpenTune for Android (roadmap M7)

A Jetpack Compose (Material3) front-end over the OpenTune Rust core, running the
whole **offline** calibration workflow on a local flash-image `.bin` — no
hardware. It calls the Rust core through the UniFFI binding in
`crates/opentune-ffi` (package `org.opentune.ffi`); the app package is
`org.opentune.app`.

## Screens

- **Open** — pick a `.bin` with the Storage Access Framework. The bytes are
  copied into app-private storage (the picked document is never modified) and
  the local path is handed to the core.
- **Identify** — reads the image's ECU identity and matches it against the
  bundled ECU definitions (`app/src/main/assets/ecudefs/`).
- **Checksum** — algorithm dropdown (`edc16` / `edc17` / `pcr21` / `crc32-tail`
  / `edc15c6`), a verify table (per-block OK/BAD, stored vs computed) and a Fix
  button that rewrites and re-verifies.
- **Maps** — pick a definition, pick a map, and decode it from the image into a
  **read-only** physical-value heat grid (blue → amber → red) with axes.
- **Flash** — the safety-gated mock flash (voltage gate → verified backup →
  write → read-back verify) against the file. No hardware is touched.

## Native library and bindings

The Kotlin bindings (`app/src/main/java/org/opentune/ffi/opentune.kt`) are
generated by UniFFI and are **checked in**. The native libraries
(`app/src/main/jniLibs/<abi>/libopentune_ffi.so`) are build artifacts and are
**not** checked in — build them with cargo-ndk:

```sh
cd android
./build-rust.sh      # builds all 4 ABIs + regenerates the bindings
```

`build-rust.sh` requires the Android NDK, `cargo-ndk`
(`cargo install cargo-ndk`) and the Rust targets:

```sh
rustup target add aarch64-linux-android armv7-linux-androideabi \
                  i686-linux-android x86_64-linux-android
```

## Building the APK

```sh
cd android
# One-time: materialise the Gradle wrapper jar (not checked in) with a local
# Gradle 8.9+, or open the project in Android Studio which does this for you:
#   gradle wrapper --gradle-version 8.9
./build-rust.sh          # native .so + bindings (needs NDK + cargo-ndk)
./gradlew assembleDebug  # the APK
```

## Build status (honest)

- `crates/opentune-ffi` **compiles, tests and generates Kotlin bindings** on a
  plain Rust toolchain — that is verified.
- The Android/Gradle/Compose side here is **written but unbuilt**: the machine
  it was authored on has the Rust toolchain but **no Android SDK/NDK, no
  `cargo-ndk`, and no Gradle wrapper jar**. To produce an APK you need those
  installed (see above). The `.so` files and `gradle/wrapper/gradle-wrapper.jar`
  are intentionally absent until then.
